# Informe de Actualización — V FSA 0018
**Fecha:** 2026-06-06

---

## Solicitud del usuario

En la tabla de proyección, las filas de transferencias no mostraban el ícono de transferencia en la columna Categoría — aparecía el ícono por defecto. En la tabla de registros sí se mostraba correctamente.

---

## Causa identificada

Ambas tablas usan la misma función `buildCatDisplay(name, type)` para renderizar el ícono de categoría:

```js
// Dentro de buildCatDisplay:
img.src = cat && cat.icon ? cat.icon : type === 'transfer' ? TRANSFER_ICON : DEFAULT_ICON;
```

La lógica es: si no hay categoría con ícono → usar `TRANSFER_ICON` si `type === 'transfer'`, sino `DEFAULT_ICON`.

**Tabla de registros** (correcto) — pasaba ambos parámetros:
```js
buildCatDisplay(tx.category || '', tx.transferLeg ? 'transfer' : tx.type)
```

**Tabla de proyección** (bug) — solo pasaba el nombre de categoría:
```js
buildCatDisplay(p.category)   // type = undefined → nunca es 'transfer' → DEFAULT_ICON
```

Como `type` era `undefined`, la condición `type === 'transfer'` siempre era `false` y se mostraba el ícono por defecto en lugar del ícono de transferencia.

---

## Modificación realizada

### JS — `renderProyeccionTable()` (`index.html`, línea ~9777)

```js
// Antes
const tdCat = tr.insertCell();
if (p.category) {
  tdCat.appendChild(buildCatDisplay(p.category));
} else {
  tdCat.textContent = '—';
}

// Ahora
const tdCat = tr.insertCell();
tdCat.appendChild(buildCatDisplay(p.category || '', p.transferLeg ? 'transfer' : p.type));
```

El patrón es idéntico al de la tabla de registros. `p.transferLeg` existe en las filas de proyección que provienen de transacciones reales (transferencias).

**Resultado:** Las transferencias en la tabla de proyección muestran el ícono de transferencia correcto, igual que en la tabla de registros. ✓
