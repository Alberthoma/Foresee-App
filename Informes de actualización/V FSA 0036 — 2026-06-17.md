# Informe de Actualización — V FSA 0036
**Fecha:** 2026-06-17

## Solicitud del usuario

Agregar una nueva vía de importación a la sección "Importar": además de CSV/Excel, poder subir una **foto/captura de pantalla** de la app bancaria (ej. historial de transacciones de Bank of America móvil) y que la app extraiga las transacciones automáticamente mediante OCR, aplicando el mismo criterio de limpieza y de-duplicación que ya usa la importación CSV/Excel.

Requisito explícito: debe poder usarse en celular eligiendo una foto ya guardada en la **galería**, no solo tomando una foto nueva con la cámara.

Decisión de arquitectura tomada con el usuario tras explorar alternativas (ver `MD/Plan OCR Importar Foto — Foresee.md` para el detalle completo del análisis):
- Se descartó usar una API de IA con visión (costo, requiere Cloud Functions + plan Blaze de Firebase — cambio de arquitectura mayor para una app que hoy es 100% estática + Firebase Auth/Firestore).
- Se eligió **Tesseract.js**, librería de OCR 100% client-side, gratis, sin servidor, sin API externa.

## Análisis previo al cambio

Se diseñó el plan completo en modo plan antes de tocar código (documentado en `MD/Plan OCR Importar Foto — Foresee.md`), incluyendo:
- El algoritmo de reconstrucción de filas de transacción a partir de las palabras con bounding boxes que devuelve Tesseract.js (no se usa el texto plano, que puede mezclar las dos columnas visuales de la captura — fecha/descripción a la izquierda, monto/saldo a la derecha).
- El shape exacto de objeto que debe producir la función OCR para conectarse al pipeline de importación CSV/Excel ya existente (`cleanBankDescription`, `pairZelleRows`, `detectImportDuplicates`, `renderImportTable`, `bulkImportTransactions`) **sin modificar su lógica interna**.
- Carga diferida (lazy) de Tesseract.js para no penalizar el arranque de la PWA a usuarios que no usan esta función.
- Manejo del caso en que el OCR detecta la fecha de una transacción pero no logra leer su monto con confianza.

## Modificaciones realizadas

### 1. Nuevo bloque de funciones OCR (`index.html` — entre `parseXLSXImport` y `pairZelleRows`, ~línea 15544)
- **Tipo:** INSERCIÓN
- Funciones agregadas: `looksLikeAmountToken`, `parseOcrAmount`, `OCR_MONTH_MAP`, `tryParseOcrDateLine`, `extractLeadingOcrDate`, `clusterWordsIntoLines`, `findColumnSplit`, `classifyRightToken`, `reconstructTransactionBlocks`, `buildDescripcionRaw`, `ocrBlocksToImportRows`, `loadTesseractLib` (+ `_tesseractLoadPromise`), `processImportImage`.
- `clusterWordsIntoLines` agrupa las palabras de Tesseract por proximidad vertical (tolerancia proporcional a la altura media de los bounding boxes) para reconstruir las líneas visuales de la captura.
- `findColumnSplit` calcula dinámicamente el punto de corte horizontal entre la columna de fecha/descripción y la de monto/saldo, buscando los tokens que "parecen monto".
- `reconstructTransactionBlocks` agrupa las líneas en bloques de transacción: detecta el inicio de cada bloque por un patrón de fecha (`"MMM D, YYYY"`, tolerante a errores de OCR), acumula las líneas de descripción siguientes, y clasifica el primer monto encontrado en la franja derecha como el monto de la transacción (el segundo, si existe, es el saldo, se descarta).
- `ocrBlocksToImportRows` convierte los bloques en objetos con el mismo shape exacto que produce `processImportRows` para CSV/Excel, pasando la descripción cruda por `cleanBankDescription()` (sin duplicar lógica de limpieza). Si no se pudo extraer un monto válido, la fila se marca `needsReview: true` con `monto: 0`, en vez de descartarse.
- `loadTesseractLib()` inyecta dinámicamente el script de Tesseract.js (CDN jsdelivr) la primera vez que se usa, evitando cargarlo en el `<head>` para todos los usuarios.
- **Por qué:** Reutilizar el 100% del pipeline existente (pareo de Zelle, detección de duplicados, preview, guardado), construyendo únicamente la capa nueva de "imagen → filas".

### 2. `processImportFile()` — nueva rama para imágenes (`index.html` — ~línea 16086)
- **Tipo:** REEMPLAZO (mínimo, aditivo)
- **Antes:** solo manejaba `.csv` y `.xlsx/.xls`; cualquier otro archivo mostraba "Formato no soportado".
- **Después:** se agregó `else if (file.type && file.type.startsWith("image/")) { newRows = await processImportImage(file); }` antes del mensaje de error.
- También se ajustó la auto-selección de filas nuevas (línea ~16119) para excluir las marcadas `needsReview: true`, forzando revisión manual antes de incluirlas en el guardado.
- **Por qué:** Único punto de entrada que necesitaba una rama nueva; el resto del flujo (concatenar a `importRows`, `pairZelleRows`, `detectImportDuplicates`, `renderImportTable`) se reutiliza sin cambios.

### 3. `showLoading()` — parámetro de mensaje opcional (`index.html` — línea 6999)
- **Tipo:** REEMPLAZO
- **Antes:** `function showLoading() { ...solo activa el overlay... }`
- **Después:** acepta un `message` opcional y actualiza el texto del overlay (`<p class="loading-text">`, ya existente en el HTML) — retrocompatible, las llamadas existentes sin argumento muestran el texto por defecto "Cargando datos...".
- **Por qué:** Mostrar el progreso del OCR ("Leyendo imagen... NN%") sin crear un nuevo elemento de UI.

### 4. `renderImportTable()` — soporte visual para `needsReview` (`index.html` — ~línea 15927)
- **Tipo:** REEMPLAZO (puntual)
- Las filas con `needsReview: true` reciben la clase `import-row-review` (resaltado ámbar) y, en la columna de monto, un `<input type="number">` editable en vez de texto — al confirmar un valor distinto de cero, la fila se actualiza (`monto`, `type`, `needsReview: false`) y se re-renderiza.
- **Por qué:** Permitir que el usuario corrija manualmente una transacción que el OCR no pudo leer con confianza, sin perder la fila ni inventar un monto.

### 5. CSS — nueva clase `.import-row-review` (`index.html` — junto a `.import-row-dup`)
- **Tipo:** INSERCIÓN
- Fondo ámbar tenue + borde izquierdo, coherente con la paleta de advertencia ya usada en `.alert-item`.

### 6. HTML de la sección Importar (`index.html` — línea ~5572-5591)
- **Tipo:** REEMPLAZO (textos + atributo)
- `accept=".csv,.xlsx,.xls"` → `accept=".csv,.xlsx,.xls,image/*"` (sin atributo `capture`, para que en celular el selector nativo ofrezca tanto Cámara como Galería/Fotos).
- Textos de ayuda actualizados para mencionar la opción de captura de pantalla (beta).
- **Por qué:** Requisito explícito del usuario de poder elegir una foto ya guardada en la galería, no solo tomar una nueva.

## Estado final

- La sección Importar ahora acepta también imágenes; al subir una, se carga Tesseract.js de forma diferida (solo la primera vez), se hace OCR, se reconstruyen las transacciones y se muestran en el mismo preview con checkboxes que ya usa CSV/Excel.
- Las filas sin monto detectable quedan marcadas para revisión manual, des-seleccionadas por defecto, con el monto editable inline.
- Se validó la sintaxis de todos los bloques `<script>` del archivo con `node --check` tras los cambios — sin errores.
- **Pendiente de prueba real en navegador**: la precisión del OCR sobre capturas reales de apps bancarias no se ha verificado todavía en este entorno (no hay forma de ejecutar Tesseract.js fuera del navegador); se recomienda probar con la captura de BoA ya compartida en la conversación y ajustar los regex de fecha/monto si la lectura no es satisfactoria.
- Documentación de referencia creada en `MD/Pipeline de Importación CSV — Referencia.md` (sesión anterior) y `MD/Plan OCR Importar Foto — Foresee.md` (esta funcionalidad).
