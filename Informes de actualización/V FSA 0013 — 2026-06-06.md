# Informe de Actualización — V FSA 0013
**Fecha:** 2026-06-06

---

## Solicitud del usuario

Dos bugs en la sección de entrada por voz:
1. Montos mayores a 9,999.99 no se reconocen correctamente
2. Palabras de ingreso ("gané", "recibí", "obtuve", "ingreso") en ocasiones no clasifican la transacción como ingreso

---

## Causas identificadas

### Bug 1 — Montos > 9,999.99

La API de reconocimiento de voz transcribe números grandes con coma de miles: `"15,000"`. La Estrategia C del parser capturaba esa cadena y hacía `parseFloat("15.000")` = **15** en lugar de 15,000. La coma de miles se interpretaba como separador decimal.

### Bug 2 — Clasificación de tipo (ingreso vs gasto)

Tres causas combinadas:

**A. Keyword faltante:** `"obtuve"`, `"percibi"`, `"ingrese"` no estaban en `VOICE_INCOME_KW`.

**B. Resolución de conflictos incorrecta:** La lógica `hasInc && !hasExp ? 'income' : 'expense'` hacía que cualquier coincidencia simultánea de keyword de ingreso Y de gasto resultara en gasto. Ejemplo: `"recibí un pago"` → `"recibi"` (ingreso) + `"pago"` (gasto) → **gasto** (incorrecto).

**C. Falso positivo por substring:** `"transferi"` (keyword de gasto) es substring de `"transferencia"`, por lo que frases como `"ingreso de transferencia"` activaban `hasExp = true` incorrectamente.

---

## Modificaciones realizadas

### 1. Keywords añadidos a `VOICE_INCOME_KW`

```js
'obtuve',   // "obtuve 500 dólares"
'percibi',  // "percibí mi sueldo"
'ingrese',  // "ingresé 1000 pesos"
```

### 2. Detección de tipo por posición del primer keyword

```js
// Antes
const hasInc = VOICE_INCOME_KW.some((kw) => norm.includes(kw));
const hasExp = VOICE_EXPENSE_KW.some((kw) => norm.includes(kw));
result.type = hasInc && !hasExp ? 'income' : 'expense';

// Ahora
const kwPos = (text, kwList) => { /* devuelve posición del primer kw encontrado */ };
const incPos = kwPos(norm, VOICE_INCOME_KW);
const expPos = kwPos(norm, VOICE_EXPENSE_KW);
result.type = incPos !== -1 && (expPos === -1 || incPos <= expPos) ? 'income' : 'expense';
```

- Usa `\b` word-boundary en lugar de `includes()` → evita que `"transferi"` coincida dentro de `"transferencia"`
- El keyword que aparece **primero en la frase** determina el tipo → `"recibí un pago"` → `"recibi"` (pos 0) < `"pago"` (pos 8) → **ingreso** ✓

### 3. Normalización de separadores de miles

```js
// Añadido justo antes de las estrategias de monto
rem = rem.replace(/\b(\d{1,3}(?:,\d{3})+)\b/g, (m) => m.replace(/,/g, ''));
// "15,000" → "15000", "1,500,000" → "1500000"
```

Ahora la Estrategia D captura `"15000"` correctamente → `parseFloat("15000")` = **15000** ✓
