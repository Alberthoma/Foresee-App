# Informe de Actualización — V FSA 0044
**Fecha:** 2026-06-19

---

## Solicitud del usuario

El usuario reportó que una transacción de Wells Fargo (archivo `Wf.csv`) se descartó al importar porque se detectó como duplicado de una transacción real de Bank of America. La causa: `detectBankImport()` no reconocía `"Wf"` como abreviación de Wells Fargo, así que la fila terminaba etiquetada con el primer banco de la lista del usuario ("Bank Of America"), coincidiendo por error con la transacción real de BoA.

Se discutió con el usuario cómo debía comportarse la detección cuando el nombre del archivo no permite identificar el banco. Se descartó tanto "adivinar con el primer banco configurado" (comportamiento actual, causa del bug) como "mostrar el nombre crudo del archivo en el dropdown" — el usuario prefirió una tercera opción: que el sistema avise con un mensaje claro pidiendo renombrar el archivo para que incluya el nombre de uno de los bancos ya configurados, y que no se importe nada hasta corregirlo.

## Análisis previo al cambio

`detectBankImport(filename)` solo reconocía tres bancos hardcodeados con un set fijo de alias (`"bank of america"`/`"boa"`, `"chase"`, `"wells fargo"`/`"wellsfargo"`), sin contemplar ni los bancos reales configurados por el usuario (`appState.banks`) ni abreviaciones como `"wf"` o `"bofa"`. Cuando no había coincidencia, devolvía el nombre crudo del archivo, y `processImportRows` lo descartaba silenciosamente reemplazándolo por `appState.banks[0]` si ese nombre crudo no estaba en la lista de bancos — exactamente la causa del bug reportado.

## Modificaciones realizadas

### 1. `detectBankImport(filename)` — coincidencia dinámica + abreviaciones condicionadas (`index.html` — línea ~15501)
- **Tipo:** REEMPLAZO
- Primero compara el nombre del archivo contra cada banco en `appState.banks` (no una lista fija) — funciona con cualquier nombre de banco que el usuario haya configurado, no solo los tres conocidos.
- Si no hay coincidencia directa, prueba abreviaciones conocidas (`boa`, `bofa` → "bank of america"; `wf`, `wellsfargo` → "wells fargo"), pero **solo las acepta si ese banco canónico está realmente en `appState.banks`** — evita sugerir un banco que el usuario no tiene configurado.
- Si nada coincide, retorna `null` en vez de un nombre crudo o un banco adivinado.

### 2. `processImportRows()` — abortar con mensaje claro si no se detecta banco (`index.html` — línea ~15552)
- **Tipo:** REEMPLAZO
- **Antes:** `const banco = appState.banks.includes(detectedBank) ? detectedBank : appState.banks[0] || detectedBank;` (adivinaba en silencio).
- **Después:** si `detectBankImport` retorna `null`, se lanza un `Error` con `err.bankNotDetected = true` y un mensaje explicando que hay que renombrar el archivo, listando los bancos configurados del usuario. No se procesa ninguna fila de ese archivo.
- **Por qué:** Decisión explícita del usuario — prefiere que el sistema avise claramente en vez de adivinar y arriesgarse a un falso duplicado o una transacción mal etiquetada.

### 3. `processImportFile()` — mostrar el mensaje específico en el catch (`index.html` — línea ~16335)
- **Tipo:** REEMPLAZO
- El `catch` ahora distingue: si el error tiene `bankNotDetected`, muestra `err.message` (el mensaje específico con la lista de bancos configurados); si no, muestra el mensaje genérico de siempre ("No se pudo leer el archivo...").

## Estado final

- Un archivo cuyo nombre no permite identificar ninguno de los bancos configurados por el usuario ya no se importa con un banco adivinado — se muestra un toast de error indicando que hay que renombrar el archivo, y no se guarda ninguna fila.
- `"Wf.csv"`, `"BofA.csv"`, `"Chase.csv"` (o cualquier variante que contenga el nombre exacto de un banco configurado) se siguen detectando correctamente.
- Pendiente que el usuario reimporte `Wf.csv` para confirmar que ahora se detecta como "Wells Fargo" y la transacción del 06/09 ya no se descarta como duplicado.
