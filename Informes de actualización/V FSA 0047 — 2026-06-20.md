**Fecha:** 2026-06-20

## Solicitud del usuario

Implementar la mejora 7 del plan de comercialización ("Escaneo de recibos OCR"): permitir que el usuario tome una foto de un ticket/factura de compra (ej. recibo de tienda) y que la app extraiga automáticamente el monto, la fecha y el comercio, pre-rellenando el formulario de nueva transacción para que el usuario solo confirme. El usuario adjuntó como ejemplo un recibo real de "Bakers World USA, LLC" para validar la extracción.

## Análisis previo al cambio

Antes de tocar código se evaluaron dos posibles puntos de entrada:

1. **Reutilizar el flujo de Importar → foto** (idea inicial del usuario): ya existe `processImportImage` (línea ~16024) con OCR client-side vía Tesseract.js para extractos bancarios.
2. **Botón nuevo en el modal de nueva transacción** (diseño ya documentado en `MD/plan-mejoras.md` línea 370-438, mejora 7).

Se recomendó la opción 2 porque el pipeline de Importar trae lógica específica de extractos bancarios que no aplica a un recibo y puede generar falsos positivos: detección de banco por nombre (`detectBankImport`), reemplazo de gasto recurrente por palabra compartida, emparejamiento Zelle, duplicados por monto+fecha+banco. Un recibo es una sola transacción, no N filas de un extracto — forzarlo por esa tabla metía riesgo innecesario. El usuario confirmó esta dirección.

Se revisó la arquitectura real del modal de nueva transacción (`openCalcModal` línea 8465, `handleCalcTotal` línea 8601, `finalizeTransaction` línea 8660) y se confirmó que fecha, descripción y banco ya viven en el mismo `calc-modal` (inputs `calc-date`, `calc-desc`, `calc-bank`) — no hace falta tocar el modal de categoría ni `finalizeTransaction`, alcanza con pre-rellenar esos tres campos.

## Modificaciones realizadas

### 1. Botón "Escanear recibo" + input de archivo oculto (`index.html` — línea ~6057-6087)
- **Tipo:** INSERCIÓN
- Botón `#calc-scan-receipt-btn` e input `#calc-receipt-input` (`accept="image/*" capture="environment"`, abre cámara trasera en móvil) dentro de `.calc-meta`, junto a fecha/descripción/banco.
- CSS nuevo `.btn-scan-receipt` (línea ~2306-2319).

### 2. Extractor de datos de recibo — funciones nuevas y separadas del OCR de extractos (`index.html` — línea ~16074-16210)
- **Tipo:** INSERCIÓN
- `loadTesseractLib()` y `clusterWordsIntoLines()` se reutilizan tal cual (ya existían). Todo lo demás es nuevo porque un recibo es 1 sola transacción con layout vertical, no N filas con fecha como un extracto:
  - `preprocessReceiptImage(file)` — convierte la foto a escala de grises + aumenta contraste vía Canvas API antes del OCR (Paso 2 del diseño original), para reducir ruido visual del fondo de la foto.
  - `extractReceiptTotal(lines)` — busca la palabra "total"/"importe"/"amount due"/"balance due" dentro de cada línea (no anclado al inicio de línea) y toma el monto que sigue en esa misma línea.
  - `extractReceiptMerchant(lines)` — ancla la detección del comercio en un sufijo legal (LLC/Inc/Corp/Co/Ltd) dentro de las primeras 10 líneas, y recorta hacia atrás hasta la primera palabra real (4+ letras) para descartar ruido OCR pegado delante. Si no encuentra sufijo legal, cae al fallback de "primera línea no vacía".
  - `extractReceiptDateDMY` + reutilización de `extractLeadingOcrDate`/`extractLeadingNumericDate` (ya existentes) para la fecha.
  - `processReceiptImage(file)` — orquesta: preprocesa, corre Tesseract con `"eng+spa"`, extrae.
  - `handleScanReceipt(file)` — pre-rellena `calc-display`/`calcExpr`, `calc-date`, `calc-desc` con lo que se detectó; si falta el monto, aplica igual lo demás y solo avisa sobre el monto faltante (antes se descartaba todo si el monto fallaba).
  - Modo debug `window.FORESEE_RECEIPT_OCR_DEBUG` (igual patrón que `FORESEE_OCR_DEBUG` de extractos) para diagnosticar con el texto crudo del OCR.

### 3. Listeners del botón (`index.html` — línea ~13427-13439)
- **Tipo:** INSERCIÓN
- Click en el botón abre el input de archivo; `change` en el input dispara `handleScanReceipt`.

### 4. Iteración de fixes con datos reales del recibo de prueba
Durante las pruebas con la foto real del usuario (recibo de Bakers World USA con fondo de sillón de cuero, que introdujo bastante ruido OCR) se identificaron y corrigieron 3 problemas con el log de debug:
- El regex de monto estaba anclado al inicio de línea (`^total`) y el ruido OCR agregaba caracteres antes de la palabra "Total" — nunca hacía match. Se cambió a búsqueda por palabra dentro de la línea.
- Si no se detectaba el monto, se descartaban también la fecha y el comercio ya extraídos correctamente. Se separó la lógica para aplicar parcialmente lo que sí se detectó.
- El comercio tomaba "la primera línea no vacía", pero el ruido del fondo de la foto se leía como texto ANTES del encabezado real del recibo. Se cambió a anclar en el sufijo legal (LLC) del nombre del comercio.
