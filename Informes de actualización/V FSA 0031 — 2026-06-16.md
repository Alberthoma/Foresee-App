# Informe de Actualización — V FSA 0031
**Fecha:** 2026-06-16

---

## Solicitud del usuario

Al importar extractos bancarios CSV/Excel, las descripciones crudas del banco son muy largas y llenas de ruido (prefijos de red, ciudades, códigos de estado, número de tarjeta). El usuario quiere que se extraiga automáticamente el nombre del comercio y el código de transacción, resultando en descripciones cortas como `"Ctlp*orlando - S306162716081496"` en lugar del texto raw completo.

Además, el criterio de detección de duplicados debía actualizarse: al limpiar la descripción, el string ya no coincide con el almacenado previamente (que era el raw en Title Case), por lo que la comparación exacta de texto fallaba. El nuevo criterio usa el código de transacción extraído como identificador.

## Análisis previo al cambio

**Flujo actual antes del cambio:**
- `processImportRows`: guardaba `row.descripcion = rawDesc` (texto crudo del banco)
- `bulkImportTransactions`: aplicaba Title Case al raw antes de guardar en Firestore
- `detectImportDuplicates`: comparaba `date + amount + bank + description` (exacto)

**Problema con duplicados post-extracción:** Una vez que `row.descripcion` es la descripción limpiada (`"Ctlp*orlando - S306162716081496"`), ya no coincide con la descripción almacenada en Firestore para importaciones anteriores (`"Purchase Authorized On 06/11 Ctlp*Orlando Healt Lakemary Fl S306162716081496 Card 0149"`). Por tanto, la comparación string-a-string siempre falla y todos los registros parecen nuevos.

**Solución de duplicados basada en código:** Extraer el código de transacción (S-code o Web Id) de ambas descripciones y comparar por código + fecha + monto. El S-code es invariante y aparece en ambas versiones de la descripción.

**Algoritmo de extracción `cleanBankDescription`:**
1. Strip de prefijos bancarios con fecha: `Purchase Authorized On MM/DD`, `Payment To`, `Pos Purchase`, etc.
2. Si el texto restante empieza con `WORD - ` (prefijo de red como "Cfx"), descartar ese token
3. Extraer código: S-code `\bS\d{12,}\b`, Web Id `\b(\d{8,})\b`, o token alfanumérico largo `\b[A-Z0-9]{12,}\b`
4. Eliminar ruido: teléfonos, estados US, fechas MM/DD, "Card XXXX", A/R, "Ending In XXXX"
5. Tomar 1-2 palabras como nombre del comercio (1 sola si contiene `*`)
6. Retornar `"Nombre - CÓDIGO"` o fallback al raw original

## Modificaciones realizadas

### 1. Nueva función `cleanBankDescription(raw)` (`index.html` — antes de `detectImportDuplicates`)
- **Tipo:** INSERCIÓN
- **Por qué:** Encapsula toda la lógica de extracción de descripción limpia. Función pura, sin efectos secundarios.

### 2. Nueva función `extractImportCode(desc)` (`index.html` — antes de `detectImportDuplicates`)
- **Tipo:** INSERCIÓN
- **Después:** Extrae el código de transacción de una descripción (S-code o número Web Id). Retorna `null` si no hay código reconocible.
- **Por qué:** Necesario para la comparación de duplicados por código.

### 3. `processImportRows()`: aplicar extracción al parsear (`index.html` — línea ~15356)
- **Tipo:** REEMPLAZO
- **Antes:** `const descripcion = rawDesc`
- **Después:**
  ```javascript
  const descripcionRaw = rawDesc;
  const descripcion = cleanBankDescription(descripcionRaw) || descripcionRaw;
  // row incluye ambos: descripcion (limpia) y descripcionRaw (original)
  ```
- **Por qué:** La extracción ocurre al parsear (no al guardar) para que el preview ya muestre la descripción limpia. `descripcionRaw` se conserva para el tooltip.
- **Nota:** `isZelle` se sigue detectando sobre `descripcionRaw` para que "Zelle Payment From..." se detecte correctamente aunque la descripción limpiada ya no contenga "zelle".

### 4. `renderImportTable()`: tooltip muestra descripción original (`index.html` — línea ~15485)
- **Tipo:** REEMPLAZO
- **Antes:** `tdDesc.dataset.tip = row.descripcion`
- **Después:** `tdDesc.dataset.tip = row.descripcionRaw || row.descripcion`
- **Por qué:** El usuario puede hover sobre la descripción limpiada y ver el texto original completo del banco para verificar que la extracción fue correcta.

### 5. `detectImportDuplicates()`: comparación por código de transacción (`index.html` — línea ~15450)
- **Tipo:** REEMPLAZO
- **Antes:** Comparación exacta de `date + amount + bank + description`
- **Después:** Si se extrae un código de la descripción importada, se compara ese código contra el código extraído de la descripción almacenada + fecha + monto. Fallback al criterio anterior si no hay código.
- **Por qué:** La descripción limpiada ya no coincide con la raw guardada en versiones anteriores. El código de transacción es invariante y permite identificar el mismo movimiento bancario independientemente del formato de la descripción.

## Estado final

- El preview de importación muestra descripciones limpias: `"Ctlp*orlando - S306162716081496"` en lugar de `"Purchase Authorized On 06/11 Ctlp*orlando Healt Lakemary Fl S306162716081496 Card 0149"`
- Al hacer hover sobre una descripción en el preview, el tooltip muestra el texto original completo del banco
- Los duplicados se detectan correctamente usando el código de transacción, independientemente del formato de descripción
- Si el algoritmo de extracción no puede reconocer el formato, retorna el raw original como fallback (nunca pierde información)
- El campo `importedFrom: 'csv'` se sigue guardando en Firestore para las siguientes versiones (V FSA 0034 lo usará para el ícono ❓)
